في مشروع ترصيد، أضف اختبارات end-to-end شاملة باستخدام Playwright.
ضع كل الاختبارات في مجلد e2e/ مع ملف playwright.config.ts

اختبر هذه السيناريوهات الكاملة:

═══════════════════════════════
1. AUTH — المصادقة
═══════════════════════════════
- إنشاء حساب جديد بنجاح → يصل للوحة التحكم
- إنشاء حساب بإيميل مستخدم مسبقاً → رسالة خطأ واضحة
- تسجيل دخول ببيانات صحيحة → يصل للوحة التحكم
- تسجيل دخول بكلمة مرور غلط → رسالة خطأ
- تسجيل خروج → يعود لصفحة الدخول
- فتح رابط محمي بدون تسجيل دخول → يحول للـ login

═══════════════════════════════
2. DASHBOARD — لوحة التحكم
═══════════════════════════════
- تظهر 4 KPI cards بأرقام (مش صفر كلها)
- تظهر آخر الفواتير
- تظهر آخر المصاريف
- تظهر آخر مبيعات الكاشير

═══════════════════════════════
3. INVOICES — الفواتير
═══════════════════════════════
- إنشاء فاتورة ببندين وضريبة 15%:
  بند 1: استشارة × 1 × 500
  بند 2: تقرير × 2 × 250
  المتوقع: إجمالي = 1150 ريال (1000 + 150 ضريبة)
- التحقق أن الفاتورة ظهرت في القائمة
- تحديد الفاتورة كمدفوعة → تغيير الحالة لـ "مدفوعة"
- فلترة الفواتير بالحالة (مدفوعة/معلقة/متأخرة)
- حذف فاتورة → تختفي من القائمة

═══════════════════════════════
4. EXPENSES — المصاريف
═══════════════════════════════
- إضافة مصروف (إيجار 3500 ريال) → يظهر في القائمة
- إضافة مصروف بمبلغ صفر → رسالة خطأ
- إضافة مصروف بدون وصف → رسالة خطأ
- حذف مصروف → يختفي من القائمة

═══════════════════════════════
5. CLIENTS — العملاء
═══════════════════════════════
- إضافة عميل جديد بالاسم والهاتف → يظهر في القائمة
- إضافة عميل بدون اسم → رسالة خطأ
- حذف عميل → يختفي من القائمة
- التحقق أن إجمالي مشترياته يظهر بجانبه

═══════════════════════════════
6. POS — الكاشير
═══════════════════════════════
- البحث عن منتج بالاسم → يظهر في نتائج البحث
- إضافة منتج للسلة → تزيد الكمية
- تغيير الكمية لـ 3 → يتحدث الإجمالي
- حذف منتج من السلة → يختفي
- إتمام البيع نقداً → تُنشأ فاتورة تلقائياً
- التحقق أن المخزون نقص بعد البيع

═══════════════════════════════
7. ACCOUNTING — المحاسبة
═══════════════════════════════
- فتح دليل الحسابات → تظهر قائمة حسابات
- إضافة حساب جديد → يظهر في القائمة
- فتح القيود اليومية → تظهر القيود
- إضافة قيد يدوي متوازن (مدين = دائن) → يُحفظ
- محاولة حفظ قيد غير متوازن → رسالة خطأ

═══════════════════════════════
8. REPORTS — التقارير
═══════════════════════════════
- فتح ميزان المراجعة → مجموع المدين = مجموع الدائن
- فتح قائمة الدخل → الإيرادات - المصاريف = صافي الربح
- فتح الميزانية العمومية → الأصول = الخصوم + حقوق الملكية
- التحقق أن أرقام التقارير تتغير بعد إضافة فاتورة جديدة

═══════════════════════════════
9. AI FEATURES — مميزات الذكاء الاصطناعي
═══════════════════════════════
- فتح المساعد المالي → يظهر الـ drawer
- إرسال سؤال "كم ربحت هذا الشهر؟" → يرجع رد (مش فراغ)
- فتح اقتراح القيد → كتابة "دفعنا إيجار 2000 نقداً" → يقترح قيداً
- التحقق أن مجموع القيد المقترح متوازن

═══════════════════════════════
10. OFFLINE — بدون إنترنت
═══════════════════════════════
- قطع الشبكة عبر Playwright
- إضافة فاتورة في وضع أوفلاين → تُحفظ محلياً
- ظهور مؤشر "غير متصل" في الـ sidebar
- استعادة الشبكة → تختفي رسالة الأوفلاين

═══════════════════════════════
11. SECURITY — الأمان
═══════════════════════════════
- محاولة الوصول لـ /manager بدون session → redirect للـ login
- محاولة الوصول لـ /admin بدون صلاحية admin → 403
- إدخال HTML في حقل الاسم → يُعرض كنص عادي (XSS protection)
- تسجيل دخول 6 مرات بكلمة مرور غلط → رسالة rate limiting

═══════════════════════════════
12. RESPONSIVE — الاستجابة للشاشات
═══════════════════════════════
- اختبر كل الصفحات على:
  desktop: 1280×720
  tablet: 768×1024
  mobile: 390×844
- تأكد أن الـ sidebar يتحول لـ menu على الموبايل
- تأكد أن الجداول تُعرض صح على الشاشات الصغيرة

═══════════════════════════════
الإعداد التقني:
═══════════════════════════════
- استخدم Playwright مع TypeScript
- قبل كل test suite: أنشئ منظمة تجريبية جديدة
- بعد كل test suite: نظف البيانات
- استخدم data-testid للعناصر بدل CSS selectors
- الـ timeout: 10000ms لكل عملية
- أضف screenshots عند الفشل
- أضف في package.json:
  "test:e2e": "playwright test"
  "test:e2e:ui": "playwright test --ui"

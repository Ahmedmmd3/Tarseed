# تدقيق صلاحيات الأدوار بحسابات منفصلة

هذا التدقيق يثبت أن صلاحيات **المحاسب والكاشير ومدير المخزن والموارد البشرية** لا تعتمد على حساب مالك المنشأة فقط.

## ما تم اختباره

| الدور | الوحدات الظاهرة | الرابط المباشر المرفوض | طلبات API المسموحة والمرفوضة |
| --- | --- | --- | --- |
| المحاسب | لوحة التحكم، الحسابات، القيود، الذمم، المصاريف، التقارير، الفوترة الإلكترونية | `/inventory` | `accounts` مسموح؛ `products` و`invoices` و`employees` مرفوضة |
| الكاشير | لوحة التحكم، نقطة البيع، المبيعات، الفوترة الإلكترونية | `/accounts` | `invoices` مسموح؛ `accounts` و`employees` مرفوضة |
| مدير المخزن | لوحة التحكم، المخزون، المشتريات | `/hr` | `products` و`warehouses` مسموحان ضمن الموقع؛ `accounts` و`employees` مرفوضتان |
| الموارد البشرية | لوحة التحكم، الموارد البشرية | `/pos` | `employees` مسموح؛ `accounts` و`products` و`invoices` مرفوضة |

كما يثبت اختبار API أن:

- كل عضو يُنشأ بحساب مستقل ودور وصلاحيات ونطاق مستودع منفصل.
- قائمة مدير المخزن لا تعرض منتج المستودع المحجوب.
- تعديل سجل خارج نطاق الموقع يُرفض بـ `403` ولا يغيّر السجل.
- تعديل أو حذف سجل تابع لمنشأة أخرى يُرفض بـ `404` ولا يكشف بياناتها.
- إدارة الفريق مرفوضة لجميع الأدوار غير المالكة.
- بعد انتهاء التدقيق تُحوّل الحسابات الأربعة إلى `inactive` ويتحقق الاختبار من حالتها عبر مسار إدارة الفريق.

## التشغيل

```bash
pnpm --filter @workspace/api-server run test:role-access
pnpm --filter @workspace/wudooh exec playwright test test/role-access.e2e.mjs --config=playwright.config.mjs
```

اختبار المتصفح يحتاج `PROD_TEST_EMAIL` و`PROD_TEST_PASSWORD` لحساب مالك مساحة الاختبار. ينشئ أعضاءً مؤقتين عبر API، ثم يعطلهم في `afterAll`، ولا يحفظ كلمات مرورهم في المستودع.

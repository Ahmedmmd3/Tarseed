---
name: جاهزية إنتاج الفوترة السعودية
description: حدّ الأمان بين تكامل الفواتير داخل النظام واعتماد الهيئة الرسمي.
---

لا تُفعّل الإرسال إلى بيئة الإنتاج أو تصفه بأنه معتمد لمجرد اكتمال إعدادات المنشأة وCSID. يجب أن يمر خط التوقيع وXML وQR وCSR باختبارات الامتثال الرسمية للهيئة وباستجابة نجاح موثقة قبل فتح الإنتاج.

**Why:** قبول HTTP أو وجود بيانات اعتماد لا يثبت أن المستند يلبي قواعد UBL/XAdES والربط الفعلي، وقد يؤدي التساهل إلى مستندات مالية مرفوضة أو مكررة.

**How to apply:** أبقِ الإنتاج محجوباً افتراضياً، وسجّل حالات إرسال ذرية تشمل نتيجة غير مؤكدة عند انقطاع الاتصال. لا تسمح بإعادة إرسال الحالة غير المؤكدة قبل التحقق من سجل الهيئة.

اجتياز مستند واحد لا يجعل وحدة الإصدار جاهزة. يجب أن تغطي حزمة Sandbox الفاتورة المبسطة والمنظمة والإشعارين الدائن والمدين، وأن تكون نتيجة كل حالة `PASS` صريحة من أداة الهيئة الرسمية.

**Why:** قبول HTTP أو نجاح حالة واحدة لا يثبت توافق المسارات والمراجع الخاصة بكل نوع مستند، وقد يفتح الإرسال لمستند لم يُختبر رسمياً.

**How to apply:** اربط قابلية إرسال كل مستند بنتيجة الحزمة التي تتضمن معرّفه، وأبطل الحزمة عند إصدار مستند موقّع جديد أو تغيير بيانات الاعتماد.

في بيئة Node الحالية لا يدعم WebCrypto منحنى `secp256k1` المطلوب لمفتاح وحدة الإصدار؛ استخدم توقيع Node Crypto بصيغة ECDSA P1363 مع Canonical XML 1.1 من libxml2، ولا تستبدله بـP-256 للتوافق الظاهري.

**Why:** تبديل المنحنى يخرج الشهادة والتوقيع عن متطلبات جهة الإصدار، بينما توقيع ECDSA بصيغة DER بدلاً من P1363 لا يطابق تمثيل XMLDSig.

**How to apply:** تحقّق محلياً من التوقيع بعد توليده، وأبقِ اجتياز أدوات الامتثال الرسمية شرطاً مستقلاً قبل فتح الإرسال.
